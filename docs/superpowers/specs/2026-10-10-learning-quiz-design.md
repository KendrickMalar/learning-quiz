# learning-quiz 設計

作成日: 2026-10-10

## 目的

読んだ本の内容や英語の品詞などを、クイズで繰り返し解いて定着させる。
仕様はシンプルに保ち、スマホ（Happy / Muxy モバイル経由の Claude Code）から解けるようにする。

## 決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| 問題の作り方 | **AI（Claude Code）に作らせる** | 手間をかけずに問題を増やせる |
| 出題の場所 | **このリポジトリで Claude Code が AskUserQuestion で出題** | アプリを作らずに済む |
| 対応エージェント | **Claude Code のみ** | 本人の指定 |
| 出題形式 | **選択式のみ（選択肢2〜4）** | AskUserQuestion の上限が4つ。形式に凝らない |
| 正誤判定と記録 | **スクリプト（`scripts/quiz.mjs`）が行う** | 採点ミスや記録の書式ぶれを防ぐ |
| 成績の閲覧 | **GitHub Pages（public リポジトリ）の HTML 1枚** | 設定が一番簡単。ビルド不要 |
| 定着の仕組み | **未回答・前回不正解・期限切れの問題を優先** | 間隔反復の最小形 |
| 管理の単位 | **セッション＝1冊の本や1つの分野の問題の束**（2026-10-10 改訂） | 読みながら少しずつ問題を足して育て、すきま時間に開き直して解くため |
| 「クイズして」の動き | **セッションを最後に触った順に並べ、選んでもらう**（2026-10-10 改訂） | チャット履歴と同じ感覚で続きを選べる |
| 時期前の問題 | **復習分を出し切ったら、次の復習日が近い順に出す**（2026-10-10 改訂） | 1つの分野を続けて反復したい場面に対応する |
| 章の記録 | **しない**（2026-10-10 改訂） | シンプルさを優先 |
| サンプル問題 | **置かない**（2026-10-10 改訂） | 本人の指定 |

## データ形式

### 問題セット `quizzes/<slug>.json`

```json
{
  "title": "英語の品詞",
  "source": "自作（中学英文法）",
  "questions": [
    {
      "id": "q001",
      "question": "\"quickly\" の品詞は？",
      "choices": ["名詞", "動詞", "形容詞", "副詞"],
      "answer": 3,
      "explanation": "-ly で終わり動詞を修飾するので副詞。"
    }
  ]
}
```

- `slug` は英小文字・数字・ハイフン。ファイル名がセットの ID になる
- `id` はセット内で一意。一度記録された ID は変えない（記録と紐づくため）
- `choices` は2〜4個、重複なし、1つ40文字以内（スマホの選択肢ボタンに収めるため）。`answer` は正解の 0 始まりの添字
- `explanation` は必須
- 問題を消すときは、記録と矛盾しないよう ID を再利用しない

### 回答記録 `results/log.jsonl`

1回答1行。

```json
{"ts":"2026-10-10T03:34:56.000Z","deck":"english-pos","id":"q001","correct":true}
```

- `ts` は UTC の ISO 8601。日付の区切りは成績ページ側で端末の時刻帯に合わせる
- 空行・壊れた行は読み飛ばす

## CLI `scripts/quiz.mjs`

| コマンド | 動作 | 出力 |
|---|---|---|
| `list` | 問題セットの一覧と、各セットの出題可能数（期限が来た問題の数） | テキスト |
| `pick <slug> [n=5]` | 出題する問題を最大 n 問選び、選択肢をシャッフルして返す | JSON |
| `record <slug> <id> <choice-text>` | 選んだ選択肢の文字列で正誤を判定し、記録に1行追記 | JSON（正誤・正解・解説） |
| `validate` | 全問題セットの形式を検査し、すべて正しければ `quizzes/index.json` を更新 | テキスト。不正なら終了コード1 |

- `pick` の出力には正解の位置を含めない（Claude が出題時に正解を漏らさないため）
- `record` は添字ではなく選択肢の文字列で判定する（シャッフル後の位置に依存しないため）。引数が空白で分かれても結合して扱う
- 存在しないセット・不正なセット名・存在しない問題 ID は、理由を表示して終了コード1

### 出題の優先順位

各問題の状態を記録から求める。

- **未回答**: 一度も答えていない
- **要復習**: 直近の回答が不正解
- **期限切れ**: 直近の回答が正解で、`最終回答日時 + 2^(連続正解数-1) 日` を過ぎている（1日→2日→4日…）
- **待機中**: 上記以外

出題順は「要復習 → 期限切れ → 未回答」。同じ区分の中はランダム。
それを出し切ったら、待機中の問題を次の復習日が近い順に出す（2026-10-10 改訂）。時期前の問題を含むときは、その旨を `message` で返す。

### 最後に触った日時

「最後に解いた日時」と、問題ファイルの `updated`（YYYY-MM-DD、任意。make-quiz が作成・追加時に今日の日付を書く）の新しいほう。`list` と成績ページはこの新しい順に並べ、どちらもないセッションは最後にする。

## 出題の流れ（`quiz` スキル）

1. 「クイズして」で起動。セットの指定がなければ `list` を見せて AskUserQuestion で選ばせる
2. `pick` で問題を取得
3. 1問ずつ AskUserQuestion で出題する（選択肢は `pick` の順のまま。「推奨」ラベルは付けない）
4. 回答ごとに `record` を実行し、正誤と解説を短く表示する
5. 終了時に正答数を表示し、`results/log.jsonl` を commit・push する（main へ直接。記録のみの commit は例外として許可）
6. 「その他」で自由入力された場合は不正解として記録する

## 問題作成の流れ（`make-quiz` スキル）

1. 本の要点・メモ・単語リストなどを受け取る
2. 問題セットの JSON を作る（既存セットへの追記なら ID を連番で続ける）
3. `validate` を通す
4. commit・push する

注意: public リポジトリのため、本文の長い引用はしない。要点を自分の言葉で問う。

## 成績ページ `index.html`

- `quizzes/index.json`、各セット、`results/log.jsonl` を fetch して表示する
- 表示内容: セットごとの正答率と回答数、日ごとの回答数と正答率の推移（直近14日）、間違いの多い問題（上位10件）
- 削除された問題の記録は「間違いの多い問題」に出さない
- スマホ幅で見やすいレイアウト。外部ライブラリは使わない

## テスト

`node --test scripts/` で次を確認する。

- `pick` の優先順位と、待機中の問題を出さないこと
- 期限の計算（連続正解数ごとの間隔）
- `record` の正誤判定と記録の追記
- `validate` が不正な形式（選択肢数、answer の範囲、ID 重複）を弾くこと

## スコープ外

- Claude Code 以外のエージェント対応
- 記述式・音声などの出題形式
- 端末をまたいだ成績の同期（記録は git で共有されるため不要）
